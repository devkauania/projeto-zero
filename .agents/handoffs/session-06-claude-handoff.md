## 6. Errors Made and Fixed This Session

### Error 1 — `.agents/prompts/` double-counted in grouped output
First pass of `generate.ts`'s section filter used
`created.filter(i => i.startsWith(".agents/prompts/"))` for Prompts, which
matched both the directory entry `.agents/prompts/` AND the files inside it.
Caught immediately in test 10's stdout: the directory appeared under both
"Directories" and "Prompts".
**Fix:** split first by trailing slash (Directories = `endsWith("/")`),
then filter prompts/config only from the files bucket. Rebuilt and
re-verified — directory now only appears in Directories.

### Error 2 — ESM anchor URL escaping in inline `node -e`
First attempted the E2E validation via `node --input-type=module -e "..."`
with a `pathToFileURL`-equivalent built from `process.cwd().replace(/\\/g,'/')`.
Bash mangled the backslashes and produced a `SyntaxError: missing )`.
**Fix:** wrote the harness to `tmp-e2e-s6.mjs` using the Write tool and
ran it directly with `node`. Used Node's own `url.pathToFileURL` instead
of hand-rolled string building. Cleaner and portable across Windows/bash.

No scope creep, no hidden iterations beyond the two above.

## 7. Known Limitations / Out of Scope

1. **Interactive clack TTY not automated.** The `p.multiselect` for
   connectors itself was not driven by a scripted TTY session — the
   reason `filterConnectors` was extracted as a pure helper. The filter
   function is what the live prompt ultimately calls, and it is exercised
   against real seed data in tests 5–9. This is the same limitation
   Session 5 documented.

2. **Do NOT reopen** for Session 7 (auditor):
   - `apps/cli/src/lib/config.ts`
   - `apps/cli/src/lib/fs-utils.ts`
   - `apps/cli/src/lib/scaffolder.ts`
   - `buildWizardConfig`'s existing behavior (the new `selectedConnectors`
     param is purely additive; default behavior when omitted is unchanged)
   - The grouping contract in `generate.ts` (covered by tests 10–11)

3. **`info` does not re-read the seed file** — it reports only what was
   persisted via `saveConfig`. This is intentional: `info` is a snapshot
   of the user's saved configuration, not the shipped defaults. If
   Session 7 wants to show "seed available vs. enabled" they would need
   a new command, not a change to `info`.

4. **`reset`'s clack confirm** respects both `p.isCancel` (Ctrl+C) and a
   plain `No` answer — both leave config untouched and print the same
   cancellation message. That's deliberate to avoid divergent error paths.

5. **No test framework installed.** Same posture as Session 5 — smoke
   tests via `node` against the compiled `dist/` artifact. Session 7 is
   the right place to decide whether to adopt vitest.
